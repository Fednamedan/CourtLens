# court-ai: ИИ-помощник для судебных документов и документов ФССП

Прототип полуфинала хакатона «ИИ-ассистенты для энергетики». Читает судебные приказы и исполнительные листы
(PDF с текстовым слоем и сканы), заполняет таблицу по образцу, помечает не извлечённое и готовит письма
юристу по фразам-маркерам.

## Состояние

| Блок | Статус |
|---|---|
| PDF с текстовым слоем, сканы (OCR Tesseract) | работает |
| Определение типа (приказ / ИЛ / эл.) | работает |
| Извлечение 20 полей, нормализация, проверка | работает на правилах, LLM добирает пропуски |
| CSV/XLSX с подсветкой «не извлечено» | работает |
| Фразы-маркеры + письмо юристу (dry-run / SMTP) | работает: 10 фраз из `data/keywords.txt`, «…» = произвольный текст между частями; на 23 образцах приказов/ИЛ ложных срабатываний нет, актов для юриста среди образцов нет |
| Бланки ИЛ с блоками должников (ocr_012–016) | работает; строка на каждого должника в `result_debtors.csv` |
| Пустые оборотные страницы сканов | отбрасываются по уверенности OCR (< 0,45) |
| Постановления ФССП (XML) | работает: теги, адрес из `DbtrAdr`, период и суммы из `IdDebtText`; отдельная таблица `result_xml.csv/xlsx` |
| Замена модели через config.yaml | реализовано, **не проверено на реальной модели** |

## Веб-клиент

```
python -m app serve            # http://127.0.0.1:8000
```

В браузере: загрузка PDF/XML (перетаскиванием), настройка писем и запуск, таблицы с подсветкой («не извлечено» - красным,
«проверить» - жёлтым), скачивание CSV/XLSX и архива писем. Три режима писем для актов, где найдены фразы-маркеры:

| Режим | Что происходит |
|---|---|
| Сохранять письма в файлы | `.eml` с вложенным актом складываются в архив `emails.zip`, ничего не отправляется |
| Отправлять по SMTP | письмо уходит через указанный сервер (STARTTLS / SSL / без шифрования); кнопки «Проверить соединение» и «Отправить тестовое письмо» |
| Не формировать письма | только таблицы, акты для юриста помечены |

Адрес сотрудника и параметры SMTP вводятся в форме и сохраняются в `data/settings.json` (пароль - открытым текстом, только для
прототипа; в боевом контуре - переменные окружения). Тот же функционал из консоли: `--notify --to ... --smtp-host ...`.

## Установка

```
pip install -e .[dev]
sudo apt install tesseract-ocr poppler-utils      # системные пакеты
# русская модель Tesseract: положить rus.traineddata в data/tessdata/
# (https://github.com/tesseract-ocr/tessdata_fast)
cp .env.example .env                              # ключи LLM и SMTP (необязательно)
```

## Запуск

```
python -m app process <папка_набора> --out out/                         # только правила
python -m app process <папка_набора> --out out/ --legal-keywords data/keywords.txt
python -m app process <папка_набора> --out out/ --llm                   # + добор полей через LLM
python -m app process <папка_набора> --out out/ --notify --to jurist@company.ru   # реальная отправка писем
# адрес получателя: --to (или поле клиентской части) важнее LEGAL_EMAIL; без --notify письма пишутся в out/emails/*.eml
python evaluation/evaluate.py out/result.csv data/labels/ocr.csv --only-present --errors
python evaluation/ocr_ablation.py                                       # сравнение предобработки OCR
python -m pytest
```

Пути в столбце «Файл» считаются от `--root` (по умолчанию - переданная папка), поэтому для сверки с эталоном
передавайте корень набора. Без `--notify` письма сохраняются в `out/emails/*.eml`, повторная отправка того же файла исключена.

## Замена модели

Всё зависящее от модели - в `config.yaml` (`llm.base_url`, `llm.model`, температура). Клиент работает с любым
OpenAI-совместимым endpoint. LLM вызывается только для полей, которые не нашли правила, и её значение принимается
лишь если дословная цитата есть в тексте документа.

## Результаты на примерах

Эталон: `data/labels/`. Оценка: `python evaluation/evaluate.py <результат.csv> <эталон.csv> --only-present --errors`.

| Набор | Документов | Совпало полей |
|---|---|---|
| Судебные акты (PDF: сканы и текстовый слой) | 23 из 23 строк эталона | 448/483 = **92,8%**; 462/483 = 95,7%, если для актов с несколькими должниками брать лучшего (`--debtors`) |
| Постановления ФССП (XML) | 21 из 21 | 482/483 = **99,8%** |

Оговорки. Правила подбирались по этим же документам, поэтому цифры оптимистичны для новых данных; настоящая
проверка - документы, которые прототип ещё не видел. В XML-таблице правила формата адреса (порядковые «5 Образцовая» →
«Образцовая 5-я» для номеров до 15, тип улицы из текста постановления) выведены по эталону 21 строки, но проверены
на всех 21 реальных XML. Для ФССП PDF-копии не обрабатываются: данные берутся из парного XML.

Примеры входов и выходов: `examples/input/xml/`, `examples/output/`.

## Ограничения

- PDF-копии постановлений ФССП распознаются и пропускаются (данные берутся из XML).
- XML: `date_start/date_end` в ФССП 013 эталон не совпадает с текстом (опечатка «20217»); в 014 `rub_deb` берётся из общей `IdDebtSum` с пометкой низкой уверенности.
- В бланках ИЛ эталон ставит в строку одного из должников (012 - второго, 015 - шестого, 016 - четвёртого), из текста это не следует: основная таблица содержит первого, остальные - `result_debtors.csv`.
- Первая версия правил на ocr_012-016 дала 85,7% (бланк другого вида, пустые страницы); после доработки 92,8%. Это показатель обобщения на неизвестный вид документа.
- Остаточные ошибки OCR-части: плохо распознанные фамилии соответчиков и цифры в ocr_002; противоречивый ocr_008
  (разные паспорта/ИНН в карточке и тексте) - противоречия пока не помечаются автоматически.
- Выбор «основного должника»: карточка должника, иначе первый в списке. Для актов, где строкой эталона служит другой
  должник (ocr_007/008, 009/010...), правило не подтверждено.
- OCR теряет отдельные цифры (дата дела в ocr_006): такие поля помечаются как не извлечённые, а не угадываются.
- В эталоне `снилс` пуст во всех строках, хотя в документах СНИЛС бывает; прототип извлекает его как факт документа.
- Образцов актов «для юриста» нет, поэтому полноту отбора проверить не на чем; фразы с «…» допускают до 200 символов между частями (возможны ложные срабатывания на «решение…отменить»).
